# Existing implementation and change boundary

- `apps/mobile/src/components/atlas-reveal.tsx` draws coarsened journey points with MapLibre and stores year/view/selected journey in component state. Point press currently toggles selection and an “Open journey” button appears above the map. The map has no preview card, empty-map dismiss handler, overlap chooser, or preserved camera state for a media viewer.
- `apps/mobile/src/reveal/types.ts` exposes an opaque local `RevealJourney.id`, generic label, period label, status, and coarse anchor. `apps/mobile/src/reveal/projection.ts` uses a generic “Available journey N” label; it has no confirmed destination name or media in Atlas state. Keep rich media outside the all-journey reveal payload and load it only for the explicit selection.
- `apps/mobile/src/reconstruction/repository.ts` resolves display IDs locally in `loadJourneyDetail` and currently limits associated memory rows to four. Its full result includes owner claim and observed span, but the four-row query is neither a complete album nor a suitable media-viewer paging contract. Query the committed projection with stable local ordering, media kind, deduplicated associations, and bounded pages for a selected journey. Keep private source refs inside the local repository/provider boundary.
- `apps/mobile/src/photo-access/provider.tsx` resolves up to four owner previews through the native adapter. `apps/mobile/src/photo-access/native-adapter.ts` already returns unavailable placeholders for cloud-only or failed local resolution without downloading. The gallery needs local video URI/poster resolution and playback state as well as photo preview resolution, while preventing stale selection publication. `expo-video` is already a mobile dependency, but current use for the Welcome video does not establish private-library video behavior.
- `apps/mobile/src/components/journey-detail.tsx` and `apps/mobile/src/app/journey/[id].tsx` provide a private detail path with four previews. `apps/mobile/src/app/journey/[id]/correct.tsx` is the existing correction route. The map card links to that correction flow as a secondary action and must preserve return context; the current correction Back chain returns through Journey detail and can reset Atlas state. The new mixed-media viewer complements these routes; existing detail does not satisfy “see all associated photos and videos.”
- The official design system already calls for a journey preview with place, time, image when permitted, and status. Existing Epic M3.2 requires shared map/list selection and dense-map handling; M3.3 requires media availability and contextual return. This spec makes the map-first interaction and gallery behavior concrete without changing the M4.1 correction contract.
- The Android development MapLibre style uses demo tiles for verification. Production style/provider selection remains a separate prerequisite for shipping the native map.
