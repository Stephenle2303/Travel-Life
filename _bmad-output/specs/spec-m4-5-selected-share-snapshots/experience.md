# Owner experience

## Entry and selection

Enter Selected Highlight from Atlas, a journey, or Replay's separate Share action. Offer link publication and existing video export as distinct labeled actions. Entering from a trip or Replay scopes candidates but selects nothing; existing export behavior remains intact. Do not require a new Replay render to share snapshot facts/media.

Match the approved prototype's cover rows, visual checkboxes, selected count, Select all, Clear and exact preview using Living Atlas tokens. Extend it with real publication controls and managed-link states. Keep Back and the primary action reachable above safe areas; accessible labels and status words accompany color. Load bounded thumbnails incrementally and retain selection while scrolling. No silent candidate cap.

Trip selection authorizes its displayed public facts, not all attached media. Media have separate explicit selection, Select all media and Clear controls. Newly available attachments never become selected automatically. A facts-only snapshot is valid when at least one eligible destination exists. Media-only choices retain their minimum selected destination context, shown in preview; no hidden facts are added.

Default public detail is named-destination centroid and month/year, or an honest unknown/relative-day label. Offer supported day-level dates or finer named-place detail only as explicit choices; never invent precision or publish original photo GPS. Keep uncertain destinations and inferred trips labeled. Counts reflect the selected snapshot, using M3.4's counting rules, never private whole-history totals.

## Exact preview and confirmation

Preview the actual sanitized draft, not a different UI projection. Show destination positions/list, chronological dates with precision, status labels, all selected thumbnails/playable media, title, expiry and generic social-preview choice. All items remain inspectable through paging. Edits invalidate confirmation. Display any unavailable media before Publish; offer retry or explicit removal and renewed preview, never silent substitution.

Before Publish show: “Anyone with this link can open or forward it”, the selected facts/media totals, expiry and “Saved copies cannot be removed.” Default expiry is 30 days; proposed adjustable choices are 1–90 whole days. Do not infer consent from opening Share. Back before confirmation retains the local draft and uploads nothing.

Publish gives immediate acknowledged progress: preparing selected copies, uploading, then publishing. Cancel stops future local work and reconciles already-started work; it cannot claim cancellation of a server activation that may have completed. If outcome is unknown, show “Checking publication” with Check status. Leave the private Atlas available. Resume the same request, not a second publish.

## Management

My shared links lists active/expired/revoked/removal-pending states, selected title, version and expiry. Copy/share appears only after confirmed activation and M4.6 viewer readiness. A closed native share sheet means handoff ended, not that a recipient received the link.

Republish opens a fresh explicit selection/preview from current eligible facts; an existing selection may be proposed only when visibly retained and revalidated. It never auto-adds new memories. Proposed default: atomic version replacement retains the URL, and old version/media references stop serving. Preserve the old active version if replacement fails. Revoke is irreversible for that URL; publishing again creates a new URL.

Expiry changes require an explicit confirmation showing the new date, update only an active owned link, and never revive revoked/expired links. Revocation asks once for the concrete chosen link, then shows server acknowledgement. Private Hide/Exclude/corrections do not silently rewrite existing snapshots; explain that an existing share stays as published and offer Revoke or previewed Republish. Only delete-all queues revocation automatically under decision 0005.

Offline revocation shows “Remote removal pending” and persists the retry. Delete-all removes private evidence while retaining only the protected remote-removal job and necessary session until acknowledgement; it does not discard the ability to remove remote shares. If credentials are unavailable, state that remote removal cannot be confirmed and show known expiry; do not create a new owner session and pretend it controls old shares. No cross-device recovery promise.

## Recovery and privacy

Use fixed error copy for access changed, selected media unavailable, quota exceeded, connection unavailable, sign-in unavailable and unknown outcome. No SQL/native/provider error text. Extend the existing closed diagnostic registry for lifecycle/failure outcomes through app-diagnostics.ts only, without content, IDs, tokens or URLs. Expected cancel/stale/offline work is a lifecycle outcome.

Recipient pages use a generic Travel Life social preview by default. Any future custom preview must be explicitly chosen and is M4.6 work; explain that social platforms may cache it. No precise dates, locations or media enter preview metadata automatically.
